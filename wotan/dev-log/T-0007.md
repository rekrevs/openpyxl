# T-0007: Fix lxml 6.x test compatibility in XML security tests

**Status**: DONE | **Size**: S

## What
Fix 4 failing tests in `openpyxl/xml/tests/test_functions.py` caused by lxml 6.x behavior.

## Log
- Root cause: The original test had two bugs:
  1. Function named `test_iterparse` but tested `fromstring` — shadowed the defusedxml test above
  2. Passed `BytesIO` to `fromstring` which expects `bytes` — broke in lxml 6.x (TypeError)
  3. Expected `ValueError` for all samples, but lxml's `resolve_entities=False` safely parses 3 of 4 samples without raising (entities simply not resolved, text=None)
- Fix: Renamed to `test_fromstring_lxml`, pass bytes directly, verify safety invariant:
  - If parsed OK: assert entity content did NOT leak (text is None)
  - If XMLSyntaxError raised: also safe (parse rejection)
- Only sample 2 (external parameter entity `%one`) raises XMLSyntaxError; samples 0, 1, 3 parse safely with unresolved entities

## Outcome
- 2709 passed, 0 failed (was 4 failed), 10 skipped, 7 xfailed
- Full regression suite clean
