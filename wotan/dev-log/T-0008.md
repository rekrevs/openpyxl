# T-0008: Investigate and preserve Python-in-Excel (PY function) cells on round-trip

**Status**: DONE | **Size**: M
**Phase**: —

## Context
Excel 365 introduced Python-in-Excel (GA September 2024), which stores =PY() function calls and Python source code directly in XLSX files. These cells use new XML elements and possibly new content types/relationships. Files containing PY cells may lose data or become corrupted when round-tripped through openpyxl if we don't preserve the relevant parts.

## Acceptance Criteria
- [x] Document what XML elements/parts Python-in-Excel adds to XLSX files
- [x] Verify whether current openpyxl preserves or loses PY cell data on round-trip
- [x] Implement preservation of unknown archive members so future features survive round-trip
- [x] Add round-trip test for unknown archive member preservation

## Approach

**Research findings:**
1. PY formula strings (`_xlfn.PY(...)`) already survive round-trip — they're just formula strings.
2. Real PY XLSX files likely contain additional parts (calcFeatures, externalCodeService, etc.) that we can't yet inspect because the MS-XLSX spec details aren't publicly documented.
3. The root problem is architectural: openpyxl uses a **whitelist writer model** — only parts it knows about are written. Unknown archive members are silently dropped.

**Implementation plan:**
Implement a general "preserve unknown archive members" feature using a tracking wrapper approach.

## Log

- Research: Unknown archive members are silently dropped (whitelist writer model)
